# Troubleshooting

## 1. `source("R/XX_....R")` gives `unexpected '['`

R double-bracket indexing must remain together:

```r
x[[field_name]]
plots[[candidate_name]]
```

Do not format it as two separate bracket lines.

## 2. A model is `NOT_YET_FIT`

Check:

- registry row is `Enabled = TRUE`
- `Fit_Model = TRUE`
- `Model_ID` matches the intended row
- requested feature names exist

Then run the master pipeline or registry runner.

## 3. “Requested feature not found”

The `Covariates` entry must exactly match a feature generated by `03_build_features.R`.

Do not silently rename a feature in only the registry.

## 4. Climate feature contains missing values

Do not replace missing lag/running values with zero. Verify that:

- the historical climate record extends far enough before 1997
- feature construction occurs before model-window filtering
- all watersheds have complete required base series

## 5. `C` audit has too few unique parameters

For current site-specific models, expected counts are 14 parameters per requested feature.

If a one-feature model reports six unique slopes, it has probably become watershed-shared and is no longer the intended site-specific parameterization.

Stop before interpreting results.

## 6. Existing fit is rejected as incompatible

The resume logic is protecting against reuse of a saved fit for a changed model definition.

If the model was intentionally changed, create a new `Model_ID` when scientifically appropriate or rerun explicitly after documenting the change. Do not bypass the protection casually.

## 7. KEM returns incomplete convergence

The fitter can trigger BFGS fallback for recognized incomplete-convergence conditions. Check the final method and final convergence field, not just the initial KEM message.

Only models ending with pipeline status `CONVERGED` should enter candidate ranking.

## 8. Model has much better likelihood but worse AICc

This can be expected with site-specific climate effects. Adding one climate feature adds 14 free coefficients; two add 28; three add 42. AICc applies a strong small-sample penalty when `K` is large relative to available observations.

Do not interpret this as a software error without checking parameter counts and formulas.

## 9. Only one model has AICc weight = 1

If only one converged model exists in a candidate set, its provisional weight is necessarily 1. That is not substantive evidence until other candidate models are fit.

The plotting code intentionally skips a candidate-set comparison figure when fewer than two converged models exist.

## 10. No parameter figure was created

Parameter figures with confidence intervals require a completed bootstrap and extracted parameter table. A fit-only candidate-screening model correctly skips CI extraction/parameter plotting.

## 11. Bootstrap wants to rerun an expensive completed model

Do not immediately proceed. Verify:

- `fit_bootstrap_CIs.rds` exists
- `bootstrap_summary.csv` says `COMPLETE`
- bootstrap `Run_ID` matches the fit `Run_ID`
- the fit itself has not been replaced

The normal runner should reuse compatible completed bootstrap results.

## 12. Master model selection crashes while arranging/selecting columns

This is a reporting-layer problem and does not imply model fits were lost. Saved `fit.rds` and `fit_summary.csv` files remain available.

Fix the reporting code and rerun `build_master_model_selection()` rather than refitting models.

## 13. AIC weights look wrong across primary and exploratory models

Weights are calculated within `Candidate_Set`. Do not combine weights from different candidate sets manually.

## 14. Clean-session run fails but development session worked

This usually indicates an object existed in the interactive workspace but was never created by the master pipeline.

Restart R and run only:

```r
setwd("F:/CRLF_MARSS")
source("00_run_full_pipeline.R")
```

Any missing-object error in this test is a real handoff issue and should be fixed before release.

## 15. GitHub rejects a large file

Run `tools/99_github_preflight.R`. Large `.rds` fits and bootstrap objects should usually be excluded through `.gitignore` and stored in an analysis archive/release system instead of normal Git history.
